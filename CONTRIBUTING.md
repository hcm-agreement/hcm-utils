# Contributing

External contributors are encouraged to [open an issue](https://github.com/hcm-agreement/hcm-utils/issues/new) before contributing code.

## Tests

Contributions need to add tests for any added code. The coverage needs to be >= 75%, though we do aim for 100% test coverage.

Run the test suite by executing
```bash
dotnet test
```

In order to generate a coverage report run
```bash
dotnet test --coverage --coverage-output-format cobertura --coverage-output coverage.cobertura.xml --coverage-settings CodeCoverage.runsettings
```

To generate a HTML report from the coverage data run
```bash
# Install ReportGenerator (only needed once)
dotnet tool install --global dotnet-reportgenerator-globaltool

# generate a HTML report
ReportGenerator -reports:tests\HCMUtils.Tests\bin\Debug\net10.0\TestResults\coverage.cobertura.xml -targetdir:CoverageReport
```

You can then open `CoverageReport/index.html` in your browser and inspect the code coverage.

## Docs

Any added code needs to be documented. We use [docfx](https://dotnet.github.io/docfx/index.html) to build human-readable documentation in addition to autogenerated docs for your IDE (should work out of the box).

To compile the docs
```bash
# Install docfx (only needed once)
dotnet tool update -g docfx

# Compile and serve the docs (go to http://localhost:8080 in your browser)
docfx .\docfx.json --serve
```

## Linting

Run

```bash
dotnet format --verify-no-changes 
```

before submitting your pull request for approval in order to verify your code conforms with the coding style of this project.


## Releasing

The following only applies to package maintainers.

In order to release a new package to nuget, [create a GitHub release](https://github.com/hcm-agreement/hcm-utils/releases/new). Make sure the correct version number is listed in the `HCMUtils.csproj` file for the package version and the assembly version. These version should be the same.

Include a meaningful release message, name it according to the version number and create a tag with that version number. Make sure to follow [semantic versioning](https://semver.org/).

Make sure all tests pass before you create the release. This is intentionally left as a manual step in order to prevent dangling tags upon test failure.

The publishing happens automatically when the tag was created.
